# MtDNA Assembly

I first baited for mtDNA reads by combining my genome and candidate mtDNA contigs (this was ```mtDNA.fasta``` from BLAST step). 

```
cat Pm_hap12_v2_20260829.fasta mtDNA.fasta > Pm_hap12_v2_20260829_mtDNA.fasta
```

Then I mapped all ONT reads to it using ```map_ont_mtdna_bait.sh```.

I filtered for read length 20-120k with ```mtdna_asm_seqkit.sh```.

I subsampled different fractions of reads and assembled a reference from each fraction of reads using hifiasm here ```pm_mtdna_hifiasm_cov.sh```. Only fraction 10% gave me a circular contig called ```ptg000001c```.

I mapped my mito reads again to ```ptg000001c``` using minimap2 and visualised in IGV: ```pm_mtdna_igv.sh```.

I annotated the mtgenome using MFAnnot ```pm_mito_mfannot.sh```.

I rotated the contig so that *cox1* would be at the start as this is convention when publishing mtgenomes. I reannotated with MFannot as rotating changes the coordinates. I also tried to convert MFAnnot output to gff3 using AGAT. All these steps are included here: ```pm_mtdna_cox1_annot.sh```. However, AGAT converter
does not export CDS features and pushes *cox1* to start at position2 for some reason. So, I used a custom python script to convert to gff3 and give me a file with proteins so I could BLAST. The python script generated by Claude (Opus 5.5) was ```mfannot2gff_prot.py```.


*Note: I also had a circular contig from my genome hifiasm assembly ```h1tg000047c``` that I was investigating as a possible candidate. As such, it is also included in all these scripts. This was simialr to ```ptg000001c``` anyway.*
